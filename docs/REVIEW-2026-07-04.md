# Repo Review — 2026-07-04

Full-repo review (iOS + server) covering **architecture**, **security**, **usability**, and
**documentation drift**. Architecture findings use the deep-module vocabulary (Ousterhout /
Pocock): *module* = interface + implementation; *deep* = lots of behaviour behind a small
interface; *shallow* = interface nearly as complex as the implementation; *seam* = where an
interface lives; *locality* = change/bugs/knowledge concentrated in one place; *deletion test* =
deleting a module either makes complexity vanish (pass-through) or reappear across callers
(earning its keep).

**Intended workflow:** validate each finding via `/grill-me`, then triage into issues
(`/to-issues`) and work them — optionally via sandcastle agent branches
(see `docs/SANDCASTLE-SETUP-PLAN.md`).

Finding IDs are stable — reference them in branches/commits (`agent/sec-2`, `agent/ios-a4`).

---

## 0. Top recommendations

1. **SEC-1 + SEC-2 together** (High): the Tailscale-only constraint is not enforced anywhere —
   port 8000 binds all interfaces AND every legacy `main.py` route (transcripts, admin deletes,
   dictionary wipe) is unauthenticated. One compose-line + one app-level dependency fixes the
   pair. Smallest effort, largest risk reduction.
2. **IOS-A11 wiring gap** (behaves like a bug): `TTSFallbackPolicy` exists and is tested but is
   **not invoked** in the live `speak` path — a Voxtral failure mid-walkthrough likely doesn't
   fall back as SPEC §15 promises.
3. **SRV-A10 → SRV-A1/A2**: adopt the existing `voxtral_client.py` adapter pattern for
   Ollama and Whisper/ffmpeg. This one through-line unlocks testability of the whole
   external-service tier.
4. **IOS-A1 decomposition via A6/A7/A8**: `WalkthroughCoordinator` at 4,859 lines is the
   single biggest locality problem in the repo; three extractions already have MARK-section
   boundaries drawn.
5. **UX-6 / DOC-1**: onboarding is a stub while the docs claim the project hasn't started —
   fix the docs now (cheap), schedule onboarding (M11) explicitly.

## 1. Architecture — iOS (`ios/`)

**Structure map.** Two `@MainActor @Observable` coordinator singletons anchor the app.
`CaptureCoordinator` (461 LOC) drives drive-by capture; `WalkthroughCoordinator` (4,859 LOC,
125 funcs) drives the evening walkthrough. Both own an `AudioEngine` actor (799 LOC, shared
input tap → M4AWriter + Parakeet downsample + wake-word sink). TTS: coordinator →
`VoiceRegistry` → {`VoxtralTTS` | `PiperTTS` | `AppleSpeechTTS`} behind the `TTSEngine`
protocol (64 LOC — the repo's best seam). Dialog: `DialogLLMResolver` → `ChainDialogLLM` →
{`GemmaDialogLLM` | `AppleFoundationLLM`} behind `DialogLLM`. Upload: coordinator →
`SessionUploader` (persistent FIFO + backoff) → `ServerClient` (multipart URLSession actor).
Heavy views: `WalkthroughView` (1,899 LOC) and `VerlaufView` (1,464 LOC), both reading
coordinator state directly and embedding business logic.

### IOS-A1 — WalkthroughCoordinator is a god module — **Strong**
- Files: `ios/Sources/Dialog/WalkthroughCoordinator.swift:1-4859`
- One `@Observable` class holds ~15 responsibilities behind a wide interface (25+ observable
  properties, ~20 public commands). Not deep — just big. Locality is inverted: opener wording,
  pickup inference, and todo confirmation all change the same file.
- **Solution:** carve out the sub-machines that already have MARK boundaries (A6/A7/A8, plus a
  `FollowUpEngine`); coordinator becomes a thin plan-runner.
- **Benefit:** each subsystem's bugs concentrate in a <400-line tested module; AI-navigability.

### IOS-A2 — `AudioEngine.wasInterrupted` is a dead interface member — **Strong**
- Files: `ios/Sources/Capture/AudioEngine.swift:660-664` (getter; set at `:176,278,617`); zero readers.
- The interruption *handling* earns its keep (chunk finalized on `.began`), but the read-side
  seam is vestigial — interface weight with zero leverage. Fails the deletion test as-is.
- **Solution:** wire it into `CaptureCoordinator.stop()` / walkthrough banner (see UX-1), or
  delete the public getter.

### IOS-A3 — Multipart upload body built entirely in RAM — **Strong**
- Files: `ios/Sources/Backend/ServerClient.swift:287-328` (`makeMultipartBody`), called `:245`
- Every audio file is appended into one growing `Data` — tens of MB resident on the code path
  most likely to run backgrounded and memory-pressured. The seam (`uploadSession`) is clean and
  deep, so the fix is local to one function.
- **Solution:** stream body to a temp file + `session.upload(for:fromFile:)`.

### IOS-A4 — Upload queue drops the whole session when one segment file is missing — **Strong**
- Files: `ios/Sources/Backend/SessionUploader.swift:115-129` (`purgeOrphans`), `:144-153` (`flush` does the same)
- Any single missing audio file discards an otherwise-complete multi-segment session; callers
  have no way to upload survivors. Recovery policy belongs *behind* the queue interface.
- **Solution:** drop only the missing file + prune its manifest segment, upload the remainder,
  mark entry partial.

### IOS-A5 — `ChainDialogLLM` is a shallow hand-expanded pass-through — **Worth exploring**
- Files: `ios/Sources/Dialog/DialogLLMResolver.swift:58-155`
- Five copy-pasted `do { primary } catch is LLMError { fallback }` blocks; a new `DialogLLM`
  method must be added in three places. The seam itself earns its keep (Gemma is a real second
  adapter) — the combinator is the shallow part.
- **Solution:** one generic `chain<T>(_ op:)` helper, or an `[any DialogLLM]` array walked by a loop.

### IOS-A6 — Opener prefetch cache embedded in the god file — **Strong**
- Files: `ios/Sources/Dialog/WalkthroughCoordinator.swift:4022-4433` + 4 cache dictionaries
- ~400 lines of genuinely deep behaviour (concurrent-FM dedup, cache-before-clear ordering,
  consume-once semantics) inline in the coordinator. The subtle ordering invariants deserve
  their own tested module.
- **Solution:** extract `OpenerPrefetcher` actor: `prefetch(segmentID:spans:)`,
  `consume(segmentID:) -> Prefetched?`, `cancelAll()`.

### IOS-A7 — Pickup/pause-marker resolution embedded in the god file — **Strong**
- Files: `ios/Sources/Dialog/WalkthroughCoordinator.swift:508-~700`
- `PauseMarker` (de)serialization, a 50-line `switch state` re-encoding every
  `WalkthroughState` case, and score-based `inferPickupPoint` — pure logic over segment
  arrays, ideal unit-test target, currently untestable without the whole coordinator.
- **Solution:** extract `PickupResolver`.

### IOS-A8 — Todo-confirmation flow split across god file + view — **Strong**
- Files: `ios/Sources/Dialog/WalkthroughCoordinator.swift:3145-3601`;
  `ios/Sources/UI/Walkthrough/WalkthroughView.swift:1401-1560` (`TodoConfirmationCard`)
- ~120 lines of pure text algorithms (sentence split, token overlap, excerpt windowing with
  `center-2`/`end-5` clamps) live inside a SwiftUI `View` — exactly where off-by-one excerpt
  bugs hide, untestable without instantiating the view.
- **Solution:** pure `TranscriptExcerpt` module (transcript + needle → text + highlight range)
  + `TodoConfirmationFlow` for the coordinator half.

### IOS-A9 — `Segment` enum switched at ~115 sites across 4 modules — **Worth exploring**
- Files: `ios/Sources/Models/Manifest.swift`, `WalkthroughCoordinator.swift`, `ChunkMerger.swift`, `VerlaufView.swift`
- Every consumer re-switches the 5-case enum to pull IDs/titles. A new section kind = editing
  four files. Shallow data type leaking its shape across seams.
- **Solution:** deepen `Segment` with `segmentID`, `displayTitle`, `audioFieldName` computed
  properties so the switch happens once inside the type.

### IOS-A10 — View pattern-matches raw walkthrough state in ~8 places — **Worth exploring**
- Files: `ios/Sources/UI/Walkthrough/WalkthroughView.swift:89,277,362,381,405,422,620-641`
- The view re-derives layout decisions from raw `WalkthroughState` cases, duplicating
  transition knowledge; coordinator exposes ~30 loose observable properties.
- **Solution:** push view intent onto `WalkthroughState` computed properties
  (`headerMode`, `showsMicRow`); consider one published `ViewState` snapshot struct.

### IOS-A12 — VerlaufView is a second god view with embedded persistence logic — **Worth exploring**
- Files: `ios/Sources/UI/Verlauf/VerlaufView.swift` (`rewriteVoiceNoteMetadata:535`,
  `deleteSegment:504`, share-merge `:949-1035`, status polling `:582`)
- A SwiftUI view rewrites `metadata.json`, deletes segments, merges audio, polls server status,
  and kicks the upload queue.
- **Solution:** extract `SessionMutations` (metadata rewrite / deletion / orphan purge) and pure
  `HistoryGrouping`.

### IOS-A13 — AudioEngine tap-callback body duplicated — **Worth exploring**
- Files: `ios/Sources/Capture/AudioEngine.swift:374-445` vs `:722-745`; converter math ×3
- The downsample block is copy-pasted across two tap closures; drift here silently drops audio
  (the file header documents past instances of exactly this bug class).
- **Solution:** single `resample(buffer:using:state:)` free function; the two taps differ only
  in sinks.

### IOS-A14 — Hardware/network boundaries have no test seams — **Worth exploring**
- Files: `AudioEngine.swift` (no protocol), `ServerClient.swift` (concrete URLSession +
  Keychain statics), coordinator `.shared` singletons throughout
- Route-change/interruption handling — the most bug-prone logic — is unreachable from tests.
- **Solution:** two narrow protocols, `AudioCapturing` and `SessionTransport`, injected into
  coordinators. Pure modules (`OpenerTemplates`, `LullDetector`, `ChunkMerger`…) show the
  pattern already exists — extend it to the two hard boundaries.

### IOS-A15 — Resolver reads UserDefaults inside the seam — **Speculative**
- Files: `ios/Sources/Dialog/DialogLLMResolver.swift:14-52` (same pattern in all `*Preferences` types)
- `current()` reaches into `UserDefaults.standard`, so tests can't resolve a chain for a given
  preference without mutating global state.
- **Solution:** `current(preference: .current)` parameter.

## 2. Architecture — Server (`server/webapp/`)

**Structure map.** FastAPI monolith. `main.py` (2,033 LOC, ~60 routes) is the historical core;
`routers/` (sessions 792, calendar 264, lightrag 196, email 166, health 164, tts 139, auth 44)
holds the iOS-era routes. Import direction is clean one-way (routers/features → db/adapters;
nothing imports `main`). `db.py` (1,514 LOC, 76 functions) is a genuinely deep repository —
but `get_pool()` leaks to 20 external call sites. Two exemplary deep adapters exist
(`voxtral_client.py`, `msgraph_client.py`: injectable transports, typed errors, constructor
config) — the template the other four external seams don't follow.

### SRV-A1 — Ollama has no adapter; the seam is re-inlined 7× — **Strong**
- Files: `llm_validator.py:21-25,288-320`, `fluency_checker.py:18-21,134-154`,
  `harvest_llm.py:14-16,36-38`, `enrichment.py:25-28,77-86`, `transcript_corrector.py:182-188`,
  `document_processor.py:27-34,216,406`
- Every caller independently reads `OLLAMA_*` env vars, opens its own `httpx.AsyncClient`,
  hand-builds `/api/chat`, re-parses errors. No Ollama call is mockable without patching each module.
- **Solution:** `OllamaClient` adapter mirroring `VoxtralClient` — injectable transport, typed
  errors, `chat(messages, *, model, num_ctx, timeout)`.

### SRV-A2 — Whisper + ffmpeg implemented twice — **Strong**
- Files: `main.py:1658-1706` vs `routers/sessions.py:736-786`
- Near-identical ffmpeg invocation and Whisper `/asr` POST, diverging in error strings and
  temp-cleanup. Deletion test: deleting either helper makes it reappear in the other caller.
- **Solution:** one shared `audio`/`AsrClient` module: `to_wav_16k_mono()`, `transcribe()`, `reachable()`.

### SRV-A3 — Config scattered: `os.getenv` in 17 files — **Worth exploring**
- `OLLAMA_BASE_URL` re-declared in 6 files with default `http://192.168.2.17:11434`; LightRAG
  reads DB-then-env while Whisper/Ollama read env directly (inconsistent precedence).
- **Solution:** per-adapter constructor config (the Voxtral pattern — mostly subsumed by SRV-A1).

### SRV-A4 — Inconsistent error modes at the HTTP interface — **Worth exploring**
- `main.py` returns hand-built `JSONResponse` dicts in ≥3 shapes (`:276,463,581` vs
  `:603-621,1753-1806` vs `:1340,1433`); `routers/*` raise `HTTPException`. Two incompatible
  error envelopes for the same app.
- **Solution:** standardize on `HTTPException` + one exception handler; map typed adapter
  errors → HTTP centrally.

### SRV-A5 — ~30 shallow CRUD pass-through routes bloat main.py — **Strong (low risk)**
- Files: `main.py:1170-1284` (persons/terms/variations/vector), `main.py:1868-2028` (org-units,
  relationships, role-assignments, static-entities, initiatives)
- Thin wrappers over `db.*` that add no behaviour, inflating the file that holds the deep
  ingest/review logic.
- **Solution:** mechanical relocation to `routers/admin.py` / `routers/dictionary.py`.
  (Do it together with SEC-2 so the moved routes gain auth.)

### SRV-A6 — Session ingest status is in-memory only — **Strong**
- Files: `routers/sessions.py:83-84` (`_session_status` dict), transitions `:297-319,404-415`
- The pipeline is a good deep module with an explicit `done/partial/failed/pending_analysis`
  state machine — but the verdict lives only in a process-local dict. Restart loses all status
  and `pending_analysis` retryability; `/api/sessions/{id}/status` returns nothing.
- **Solution:** persist session+segment status to a table (mirror `ingest_uploads`); memory
  becomes a cache. (Interacts with UX-4's 409 semantics.)

### SRV-A7 — Two divergent ingest pipelines — **Worth exploring**
- Files: `main.py:1709-1806` (`/api/ingest/upload`) vs `routers/sessions.py:101-415` (`/api/sessions`)
- Both do audio → ffmpeg → Whisper → persist, with separate helpers, separate failure
  bookkeeping (DB table vs in-memory dict), duplicated retry.
- **Solution:** after SRV-A2/A6, express single-file ingest as a one-segment session, or share
  the transcribe+persist core.

### SRV-A8 — Raw SQL leaks out of db.py into handlers — **Worth exploring**
- `get_pool()` called 20× outside db.py; inline SQL at `main.py:185,750-752,786,1780-1783`.
- **Solution:** add the ~5 missing named query functions to `db.py`; make the pool private.

### SRV-A9 — Qdrant seam is soft, not hard — **Speculative**
- Files: `vector_store.py:26-52` — module-global client from env, lazy import, "disabled"
  invariant leaked as a global flag.
- **Solution:** constructor-injected client; null-object adapter for disabled state. Only pays
  off if vector search grows.

### SRV-A10 — Adapter quality is bimodal; codify the good template — **Strong (through-line)**
- Good: `voxtral_client.py:67-228` (+ `tests/test_voxtral_client.py`, MockTransport, one test
  per error branch), `msgraph_client.py:80-224`. Weak: Ollama, Whisper, Qdrant, LightRAG
  (`document_processor.py:62-133,159,213,404,780`).
- Test coverage mirrors this exactly — only the two good adapters (plus pure markdown helpers)
  have tests; everything behind inlined `httpx` calls is untestable without a live service.
- **Solution:** treat Voxtral as the reference pattern; LightRAG is the next-best extraction
  after Ollama/Whisper.

### SRV-A11 — Trivial cleanups — **Strong (5 minutes)**
- `main.py:777` — the repo's single remaining n8n reference (a comment); delete it.
- `diary_processor` occurrences elsewhere are the legitimate Postgres DB name — leave them.

## 3. Security

Threat model honored: single-user personal tool, Tailscale-only by design, single static bearer
token accepted. Findings below are things the threat model does *not* accept.

### SEC-1 — **High** — Port 8000 bound to all host interfaces; Docker bypasses host firewalls
- Files: `server/docker-compose.yml:4-5` (`"8000:8000"`), `server/webapp/Dockerfile:12`
  (`--host 0.0.0.0`)
- The publish spec binds `0.0.0.0:8000`, and Docker's iptables rules bypass `ufw`. Constraint
  #6 ("Tailscale, not public endpoints") is enforced by nothing in the repo.
- Failure: any non-Tailscale interface on the host (home LAN, public NIC) exposes every
  endpoint — combined with SEC-2, full unauthenticated data/admin access.
- **Fix:** bind the publish to the tailnet IP (`"100.x.y.z:8000:8000"`, via env var) or
  `127.0.0.1` behind a tailnet-only proxy.

### SEC-2 — **High** — Entire legacy HTMX/admin/data API is unauthenticated on the same port
- Files: 77 `@app.*` routes in `main.py` without `Depends(require_bearer)`, incl.
  `POST /api/transcripts/delete` (`:737`), `POST /api/data/clear-dictionary` (`:1133`),
  `DELETE /api/admin/persons/{id}` (`:1186`), `GET /review/{transcript_id}` (`:218`, full
  transcript content), `POST /api/ingest/clear-history` (`:1651`)
- `routers/__init__.py:3-6` claims these "stay open on the Docker network" — false: they share
  the published port with the bearer-gated routers. The bearer token protects calendar/email/tts
  while all diary transcripts and destructive admin ops are open.
- **Fix:** app-level `require_bearer` dependency with a small allowlist (`/health`), or split
  the admin UI onto a `127.0.0.1`-only app.

### SEC-3 — **Medium** — Exported diary audio written with `URLFileProtection.none`
- Files: `ios/Sources/Storage/AudioMerger.swift:276-277,288-290`,
  `ios/Sources/UI/Verlauf/VerlaufView.swift:1076-1078`
- Share-staged merged M4As are readable pre-first-unlock — weaker than the accepted
  `.completeUntilFirstUserAuthentication` baseline, and applied to real diary content.
- **Fix:** use `.completeUntilFirstUserAuthentication` for share staging; delete temp exports
  after the share completes.

### SEC-4 — **Low** — Hardcoded `diary:diary` Postgres credentials
- Files: `server/docker-compose.yml:104-105`
- Mitigated by no host port publish; becomes load-bearing the day someone maps 5432 for debugging.
- **Fix:** generated password via `.env`.

### SEC-5 — **Low** — String-interpolated SQL in the offline nocodb import tool
- Files: `server/webapp/import_nocodb.py:64,106-112,137-140,165-169,192-194`
- Operator-run migration script; safety rests entirely on hand-rolled `sql_escape()`.
- **Fix:** parameterized statements via asyncpg, or unit-test `sql_escape` edge cases.

### SEC-6 — **Low** — LLM output derived from transcripts trusted without validation
- Files: `server/webapp/harvest_llm.py:22-74` (`category` passed through unvalidated at `:70`;
  `estimated_hours` is clamped), `routers/sessions.py:608-628`
- Transcript → Ollama → Harvest entries / knowledge-graph narrative is an unvalidated trust
  boundary (prompt-injection surface, largely accepted for single-user).
- **Fix:** allowlist `category`, bound lengths; document the trust boundary.

### SEC-7 — **Info** — Spoken command token logged `.public`
- Files: `ios/Sources/Capture/WakeWordDetector.swift:171` via `Logging.swift:37`
- Scope limited to the matched command word, but inconsistent with the codebase's own
  transcript-privacy rule (`Logging.swift:12-13`).
- **Fix:** `.private` interpolation for the token.

**Verified clean (no action):** constant-time bearer compare failing closed
(`routers/auth.py:26-44`); ffmpeg via argv `create_subprocess_exec`, no `shell=True`; multipart
path traversal blocked (`_safe_relative_path`, slugified session dir); parameterized SQL with
whitelisted identifiers in `db.py`/routers; no SSRF (all service URLs from env); `.env`/`data/`/
`msal_cache.bin` gitignored + untracked, cache written `0600` atomically; minimal Graph scopes;
tokens redacted in logs; sidecar containers unbound from host; ATS exception scoped to `ts.net`;
Keychain `AfterFirstUnlockThisDeviceOnly`; Live Activity payload carries no diary content.

## 4. Usability

### UX-1 — **Medium** — Recording interruption never surfaced to the user
- Files: `ios/Sources/Capture/AudioEngine.swift:664` — same root as IOS-A2.
- A phone call / Siri / alarm mid-capture silently truncates the recording; the property's own
  doc comment promises a notice that no one implements.
- **Fix:** read `wasInterrupted` after stop; banner "Aufnahme wurde unterbrochen — willst du
  weitermachen?"

### UX-2 — **Low** — Disk-full shows raw Swift error string
- Files: `ios/Sources/Capture/CaptureCoordinator.swift:337` → `CaptureView.swift:42-43`
- Audio is correctly preserved (honours SPEC §15.2) but the user sees an interpolated `NSError`.
- **Fix:** map known domains (out-of-space) to a localized recovery-oriented message.

### UX-3 — **Low** — Enrichment failure copy diverges from SPEC §15
- Files: `WalkthroughCoordinator.swift:2314-2323` vs `SPEC.md:965-985`
- Failure *is* surfaced (good) but doesn't distinguish server-unreachable from other failures
  ("Can't reach server. Enrichment skipped." promise loosely met).

### UX-4 — **Low** — Lost-response retry marks a successful session as permanently failed
- Files: `ios/Sources/Backend/SessionUploader.swift:88,208-212`, `server/webapp/routers/sessions.py:140-145`
- Duplication itself is now well-mitigated (client dedup, server 409, partial-dir cleanup). The
  residual: if the 200 response is lost in transit, retry → 409 → entry marked
  `permanentlyFailed` although ingestion succeeded. False negative in Diagnostics, no data loss.
- **Fix:** treat 409 as success. (Cleaner after SRV-A6 persists real status.)

### UX-5 — **Low** — No "repeat this opener" affordance
- Files: `WalkthroughCoordinator.swift:2792-3060`, `WalkthroughView.swift:148-193`
- Lull machine, 15s prompt, 24s auto-advance, skip/pause/resume/abort all verified working.
  Only gap: a user who missed the spoken opener has no replay control, just the transcript row.

### UX-6 — **High** — Onboarding (SPEC §14) is entirely unimplemented
- Files: `ios/Sources/UI/Onboarding/_OnboardingPlaceholder.swift` (stub),
  `VoiceDiaryApp.swift:224-260` (no first-launch gate), `:85` (permissions fired silently at launch)
- A clean install lands on the Evening tab with no server configured; first captures fail
  silently into the retry queue until the user stumbles onto More → Server. None of §14's 10
  steps exist.
- **Fix:** M11 onboarding gate; at minimum first-run server-setup + permissions priming.

### UX-7 — **Medium** — Server setup lacks URL validation and an onboarding entry point
- Files: `ios/Sources/UI/Settings/DebugSettingsView.swift:172-226`
- Good: trims input, Keychain write, `/health` check, 401-specific message, status pill.
  Gaps: no URL-format validation (malformed URL → generic "down"), default `"http://"` value
  saves to an opaque failure, and the screen lives in a file named `DebugSettingsView.swift`.

### UX-8 — resolved — Gemma background-suspend download
- `DialogModelSettingsView.swift:386` shows a clear pause message + recovery + Apple-model
  fallback. No action.

### UX-9 — **Medium** — DisplayTimer fixed at 64 pt, no Dynamic Type
- Files: `ios/Sources/UI/Chrome/DisplayTimer.swift:20` (fixed 64 pt + 80 pt frame)
- Body/title fonts now scale via `Theme.font` `relativeTo:` (fixed since last review); the
  timer (drive-by counter + walkthrough listening counter) is the residual.
- **Fix:** `@ScaledMetric` or `relativeTo:`, or flexible slot.

### UX-10 — **Medium** — Sparse VoiceOver coverage on custom chrome
- 8 `accessibilityLabel` calls repo-wide. `PlayPauseDisc` call sites are labelled;
  `DisplayTimer`, `DSStatusPill`, `IconDisc`, `BottomActionStack`, most Settings rows are not.
  No `accessibilityValue` on the live timer; custom discs may lack `.isButton` trait.
- **Fix:** audit `Chrome/`; stable label + value for the timer.

### UX-11 — **Low** — No reduced-motion support
- No `accessibilityReduceMotion` reads anywhere; StatePill/walkthrough animations always run.

### UX-12 — **Medium** — HTMX review UI: thin empty states and no save feedback
- Files: `server/webapp/templates/review.html:88,118,122-124`
- "Loading…" placeholders with no empty state, no confirmation after manual Save/entity add,

### UX-13 — **Medium** — Settings surface far thinner than SPEC §12
- Files: `SPEC.md:838-879` vs `WalkthroughSettings.swift:151-157`, `LanguageSettingsView.swift`,
  `_SettingsPlaceholder.swift`

- **Fix:** implement, or amend SPEC §12 to the intentionally-reduced surface — decide per item
  in the grilling session.
